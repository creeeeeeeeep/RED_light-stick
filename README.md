# 레드 응원봉

흔들면 치지직 채팅에 이모티콘이 쌓이고, 버튼을 누르면 전송되는 응원봉.
RED레드 채널 팬들에게 **무상 배포**할 목적으로 만든다 (판매·광고 없음).

```
봉(ESP32-S3) ──HTTP POST──▶ 중계 서버 ──WebSocket──▶ 크롬 확장 ──▶ 치지직 채팅
```

팬이 하는 일은 **확장을 설치하고, 봉을 USB로 연결해 WiFi를 넣는 것**뿐이다.
그 뒤로는 전원만 연결하면 되고, 펌웨어는 OTA로 알아서 갱신된다.

> ### 📘 [설치 안내 (팬용)](docs/설치가이드.md)
> 응원봉을 받으신 분은 이쪽입니다. 비전공자 기준으로 처음부터 끝까지 적었습니다.

## 구성

| 폴더 | 무엇 | 언어 |
|---|---|---|
| `firmware/` | 봉 펌웨어 — 모션 인식, LED, WiFi, OTA | C (ESP-IDF v5.5) |
| `server/` | 중계 서버 | Python (aiohttp) |
| `extension/` | 크롬 확장 — 채팅에 이모티콘을 넣는다 | JS (Manifest V3) |
| `docs/` | 치지직 내부 구조 조사 기록 | 문서 + 조사 스크립트 |

하드웨어는 **Waveshare ESP32-S3-Matrix** (8x8 WS2812 + QMI8658 6축 IMU) 하나로,
LED와 IMU가 보드에 이미 붙어 있어 **전송 버튼만 납땜하면 된다** (GPIO2 + GND).

## 어떻게 동작하나

**모션 인식.** 가속도를 중력 방향과 그에 수직인 성분으로 나눠 좌우 흔들기 /
위아래 찍기 / 격하게 흔들기를 가른다. 보드를 어느 방향으로 넣든 중력을 매
순간 추정하므로 판정이 같다.

**이모티콘 입력.** 치지직은 채팅 입력창에 직접 넣는 것을 막는다. 그래서 확장이
**이모티콘 피커를 화면에서 감춘 채로 열어 해당 버튼을 대신 클릭한다.** 치지직이
보기에는 사용자가 직접 고른 것과 구별되지 않는다.

**전송은 사람이.** 흔들면 쌓이기만 하고, 물리 버튼을 눌러야 채팅에 나간다.
"사람의 1회 조작 = 채팅 1건" 을 지키기 위한 구조이며, 자동·주기 전송은 넣지 않는다.

## 시작하기

```bash
# 1. 서버
cd server && py -m pip install aiohttp && py server.py

# 2. 확장 — chrome://extensions 에서 "압축해제된 확장 프로그램 로드"
#    → extension 폴더 선택

# 3. 펌웨어
cd firmware && .\crown.bat        # 인자 없이 실행하면 메뉴가 뜬다
```

봉을 굽고 나면 확장의 **옵션 페이지**를 열어 WiFi를 넣는다. 방 코드와 토큰은
자동으로 만들어져 봉과 확장에 동시에 저장되므로 직접 입력할 것이 없다.

자세한 것은 [`firmware/README.md`](firmware/README.md) 와
[`docs/작업일지.md`](docs/작업일지.md) 를 보면 된다. 작업일지에는 **밟았던 함정**이
정리돼 있어서 같은 데서 두 번 막히지 않는다.

## 아직 안 된 것

- **펌웨어 서명** — 지금은 그 주소에서 오는 바이너리면 무엇이든 굽는다.
  팬에게 배포하기 전에 반드시 붙여야 한다.
- **서버가 LAN 전용** — 집 밖 봉이 붙으려면 HTTPS 터널이 필요하다.
- **확장이 웹스토어에 없음** — 지금은 개발자 모드로 설치해야 한다.
- **임계값 튜닝** — 지금 값은 맨보드를 손으로 흔든 데이터로 맞춘 것이라,
  크라운을 달면 다시 잡아야 한다.

## 설정 파일

`server/config.json` 은 저장소에 없다. `config.example.json` 을 복사해서 쓴다.

```bash
cp server/config.example.json server/config.json
```

`admin_token` 은 **아무 방에나 들어갈 수 있는 만능 키**이므로 반드시 바꿀 것.
`server/rooms.json` 에는 팬마다의 토큰이 들어가므로 절대 공개하지 않는다
(둘 다 `.gitignore` 에 들어 있다).
