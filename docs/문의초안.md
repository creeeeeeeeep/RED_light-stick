# 치지직 문의 초안

추측으로 판단할 문제가 아니라서 직접 물어보는 쪽이 정확하다.
아래를 복사해 쓰되, 채널명·규모 등은 실제에 맞게 고칠 것.

## 문의처

공식 API 문서(chzzk.gitbook.io)에는 연락처가 전혀 적혀 있지 않다.
아래는 확인 가능한 순서대로.

### 1순위 — 스트리머를 통해서 (가장 빠름)

특정 채널 굿즈로 만드는 것이라면, **스트리머 본인이 치지직 담당자에게
물어보는 쪽이 압도적으로 빠르고 정확하다.** 파트너 스트리머에게는 보통
담당 매니저 연락처가 있고, 일반 고객센터 티켓처럼 정형 답변이 돌아오지 않는다.
게다가 스트리머 채널 굿즈 건이라 스트리머가 물어보는 게 자연스럽다.

### 2순위 — 치지직 개발자센터

https://developers.chzzk.naver.com 로그인 후, 상단/하단 메뉴나 앱 상세 화면에
문의 링크가 있는지 확인. 이미 앱을 등록해 둔 곳이라 API 관련 질문이면 여기가 맞다.

### 3순위 — 치지직 고객센터

치지직 웹/앱에서 **우측 상단 프로필 아이콘 → 메뉴에서 고객센터**.
또는 네이버 통합 고객센터(help.naver.com)에서 치지직 검색.

### 4순위 — 치지직 공식 SNS

공식 X(트위터) 계정에 문의 경로를 물어보면 안내받을 수 있다.

## 초안

> **제목: 물리 응원봉(하드웨어) 버튼을 통한 채팅 전송이 약관상 허용되는지 문의드립니다**
>
> 안녕하세요.
>
> 시청자에게 배포할 물리 응원봉 기기를 제작 중입니다. 약관 위반 소지가 있는지
> 미리 확인하고 싶어 문의드립니다.
>
> 먼저 밝혀두면, 이 기기는 **무상으로 배포**하며 판매하지 않습니다.
> 광고 삽입이나 시청자로부터 대가를 받는 요소는 일절 없습니다.
>
> **기기 동작 방식**
>
> 1. 시청자가 응원봉을 흔들면, 흔든 동작이 **기기 내부에만** 기록됩니다.
>    이 단계에서는 치지직 서버와 어떤 통신도 하지 않습니다.
>    (기기의 LED에 쌓인 개수가 표시될 뿐입니다)
> 2. 시청자가 응원봉의 **물리 버튼을 직접 누르면**, 그때 채팅 1건이 전송됩니다.
> 3. 버튼을 한 번 누를 때마다 채팅은 정확히 1건만 나갑니다.
>    시간에 따라 자동으로 전송되거나, 사람의 조작 없이 전송되는 경우는 없습니다.
> 4. 전송되는 채팅은 시청자 **본인 계정**으로 나가며, 본인이 사용 권한을 가진
>    이모티콘만 사용합니다.
>
> 요약하면 매크로 키보드나 게임패드처럼 **외부 입력장치**로 채팅을 입력하는
> 형태이고, "사람의 물리적 조작 1회 = 채팅 1건" 원칙을 지킵니다.
>
> **문의 사항**
>
> 1. 위와 같이 외부 하드웨어 버튼을 통해 채팅을 전송하는 방식이 허용되는지요?
>    "사람의 물리적 조작 1회 = 채팅 1건" 원칙을 지키더라도 자동화 도구로
>    간주되는지 궁금합니다.
>
> 2. **치지직 API 이용약관 제13조**(사용자로부터 애플리케이션 이용에 대한
>    대가를 제공받는 행위 금지)와 관련하여, 위와 같이 **무상으로 배포하고
>    광고나 어떠한 대가도 받지 않는 경우** 해당 조항에 저촉되지 않는 것으로
>    이해하고 있습니다. 이 이해가 맞는지 확인 부탁드립니다.
>
> 3. **제11조**와 관련하여, 각 시청자가 OAuth로 **본인 계정을 직접 인증**하고
>    본인 토큰으로 채팅을 전송하는 구조는 "제3자로 하여금 API 서비스를
>    이용하도록 하는 행위"에 해당하는지요?
>    클라이언트 아이디나 토큰을 공유하지는 않습니다.
>
> 4. 현재 공식 오픈 API의 `POST /open/v1/chats/send` 는 `message` 필드만
>    지원해서 치지직 이모티콘을 전송할 수 없는 것으로 확인했습니다.
>    (`{:d_1:}` 형태로 보내면 문자 그대로 표시됩니다)
>    **공식 API에서 이모티콘 전송을 지원할 계획이 있으신지요?**
>    지원된다면 저희는 공식 API만으로 구현하겠습니다.
>
> 5. **만약 공식 API에서 이모티콘 전송을 지원할 계획이 없다면**, 브라우저
>    확장 프로그램 방식으로 구현해도 되는지요?
>
>    구현 방식을 숨김 없이 말씀드리면 이렇습니다.
>    - 확장이 시청자 본인의 브라우저에서 동작합니다
>    - 이모티콘을 넣을 때 **치지직 이모티콘 선택창을 프로그램적으로 열고
>      해당 이모티콘 버튼을 클릭**합니다. 사람이 마우스로 하는 동작과 같은
>      경로이며, 채팅 전송 데이터는 치지직 웹 클라이언트가 직접 생성합니다
>    - 선택창이 화면에서 깜빡이지 않도록 그 순간 CSS로 보이지 않게 처리합니다
>      (시청자 본인 화면의 시각적 처리이며, 전송 경로는 동일합니다)
>    - 전송은 채팅 입력창에 **엔터 키 이벤트**를 발생시켜 이루어집니다
>
>    지켜지는 조건은 앞서 말씀드린 것과 같습니다.
>    - 시청자 본인 계정, 본인이 사용 권한을 가진 이모티콘만 사용
>    - 물리 버튼 조작 1회당 채팅 1건, 자동·주기적 전송 없음
>    - 사람이 직접 조작하는 속도를 넘지 않음
>
>    참고로 유사한 기능의 확장 프로그램(치지직 이모티콘을 단축키로 입력하는
>    도구)이 이미 Chrome 웹스토어에 공개되어 있는 것으로 압니다. 다만 그것이
>    치지직에서 허용하신 것인지는 알 수 없어 저희는 직접 확인받고자 합니다.
>
>    허용이 어렵다면 어떤 조건이면 가능한지, 또는 권장하시는 대안이 있는지
>    알려주시면 그에 맞추겠습니다.
>
>    (이 방식은 공식 API를 사용하지 않으므로 API 이용약관이 아닌 일반
>    이용약관의 적용을 받는 것으로 이해하고 있습니다. 그 부분도 함께 확인
>    부탁드립니다.)
>
> 6. 이 기기는 다수의 시청자에게 배포할 예정입니다. 배포 규모에 따라
>    별도로 협의하거나 승인받아야 하는 절차가 있다면 알려주시면 따르겠습니다.
>
> 시청자분들의 계정에 불이익이 가지 않는 것이 가장 중요하다고 생각해서
> 개발 전에 먼저 여쭙습니다. 답변 부탁드립니다. 감사합니다.

## 이렇게 쓴 이유

- **동작을 구체적으로 적었다.** "응원봉 만드는데 되나요?" 같은 질문은
  "약관을 참고하세요" 라는 정형 답변만 돌아온다.
- **"사람 조작 1회 = 채팅 1건"을 명시했다.** 자동화 판단의 핵심 쟁점이다.
- **무상 배포임을 맨 앞에 밝혔다.** 13조(대가 수령 금지)를 피하는 것도 있지만,
  상업적 이용이 아니라는 점 자체가 허용 판단을 크게 유리하게 만든다.
  2번은 그래서 "저촉되지 않는 것으로 이해한다, 맞는지" 하는 확인 질문으로 뒀다.
  나중에 원가 회수 명목이라도 돈을 받게 되면 이 답변은 무효가 되니 주의.
- **4·5번이 짝이다.** "지원 계획이 있냐 → 없으면 웹소켓으로 쏴도 되냐"로
  이어지게 해서, 어느 쪽 답이 와도 다음 행동이 정해지게 만들었다.
  회색지대를 문서화된 예/아니오로 바꾸는 것이 목적이다.
- **6번으로 배포 규모를 먼저 밝혔다.** 나중에 문제 삼기 어려워진다.

## 물어보는 것의 대가

5번처럼 대놓고 물으면 "안 됩니다"라는 답이 명시적으로 남을 수 있다.
안 물었으면 조용히 넘어갔을 수도 있는 길이 닫히는 셈이다.

그럼에도 물어보는 게 맞다. 위험이 **내 계정이 아니라 팬들 계정**에 가고,
수백 명에게 배포한 뒤 문제가 터지면 되돌릴 방법이 없기 때문이다.
반대로 "된다"는 답을 받아두면 그게 가장 강력한 보호막이 된다.

## 답변을 받은 뒤

- **허용된다는 답** → 그 답변을 보관해 둘 것. 나중에 문제가 생겨도 근거가 된다.
- **안 된다는 답** → OBS 오버레이 방식으로 전환. 봉 펌웨어·모션 인식·큐·버튼은
  그대로 쓰고 마지막 출력단만 바꾸면 된다.
- **답이 없거나 애매한 답** → 배포는 보류하고 본인 계정으로만 테스트.
  애매한 답을 허락으로 읽지 말 것.
