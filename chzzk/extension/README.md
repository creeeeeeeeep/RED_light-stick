# 크라운 응원봉 — 크롬 확장 (프로토타입 v0.3)

응원봉을 흔들면 채팅 입력창에 이모티콘이 쌓이고, 봉의 버튼을 누르면 전송된다.
**현재 단계: 브라우저 쪽 동작 검증 완료.** 봉/중계는 아직 안 붙었다.

---

## 이 확장은 채팅을 직접 전송하지 않는다

사람이 키보드로 하는 것과 똑같은 경로를 쓴다.

```
1) 채팅 입력창에 이모티콘 <img> 를 넣는다   ← 타이핑과 동일
2) 엔터 키 이벤트를 발생시킨다              ← 전송
```

전송 프레임은 **치지직 코드가 스스로 만든다.** 우리는 만들지 않는다.

### 왜 방식을 바꿨나

처음에는 WebSocket 에 프레임을 직접 밀어넣는 방식으로 만들었고 실제로 동작했다
(`legacy-websocket-inject.js` 에 보존). 하지만 세 가지 문제가 있었다.

- 치지직 API 이용약관 **16·17조**(회사가 정한 범위/방법을 초과한 사용)에 걸릴
  소지가 크다
- 서버 입장에서 사람이 UI를 조작한 흔적이 없어 봇 트래픽으로 보인다
- 팬 수백 명에게 배포하면 **동일한 프레임 패턴 자체가 서명**이 된다

입력창 경유 방식은 프로토콜 수준에서 사람과 구분되지 않는다.
"사람 조작 1회 = 채팅 1건" 원칙도 그대로 유지된다.

> 약관 확인은 여전히 필요하다. 방식을 바꿨다고 자동으로 허용되는 것은 아니다.
> `../문의초안.md` 참고.

## 실측으로 확인한 것

**1. 채팅이 iframe 안에 있다**
`https://chzzk.naver.com/iframe/live/{channelId}/chat` — 최상위 페이지에만
스크립트를 넣으면 채팅에 닿지 못한다. 그래서 `all_frames: true`.

**2. 입력창은 contenteditable 이고 이모티콘은 `<img>` 다**
`<pre contenteditable="true">` 안에 이모티콘이 `<img src='...'>` 로 들어간다.
`{:d_1:}` 을 텍스트로 타이핑하면 글자 그대로 나가는 이유가 이것이다.
직렬화기가 `<img>` 만 이모티콘으로 인식한다.

**3. react-contenteditable 계열이다**
컴포넌트가 `html` / `innerRef` / `tagName` prop 을 받는다.
DOM 을 고치고 `input` 이벤트를 발생시키면 리액트 상태가 알아서 동기화된다.
그래서 `world: "MAIN"` 이 필요하다 — 격리 월드에서는 페이지의 DOM 처리에
제대로 개입할 수 없다.

**4. 전송 버튼이 없다**
입력 여부에 따라 활성화되는 버튼을 찾아봤지만 없었다. 엔터로만 보낸다.

## 설치

1. 크롬 주소창에 `chrome://extensions`
2. 우상단 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드** → 이 `extension` 폴더 선택

## 사용

1. 치지직 방송 페이지를 연다 (채팅이 보여야 한다)
2. 확장 아이콘 클릭 → 이모티콘 ID 입력 → **입력창에 추가**
3. 입력창에 이모티콘이 쌓이는 것을 확인한 뒤 **전송**

WebSocket 방식과 달리 **사전 학습이 필요 없다.** 채팅을 미리 칠 필요도 없다.

## 콘솔에서 직접 테스트

확장 설치 없이도 `inject.js` 내용을 콘솔에 붙여넣으면 그대로 동작한다.
채팅 iframe 을 단독 탭으로 열고 F12 → Console 에서:

```js
crown.status()                          // 상태 확인
crown.list('redred')                    // 사용 가능한 이모티콘 검색
crown.add('redredLight')                // 입력창에 하나 추가 (전송 안 함)
crown.send()                            // 전송 (엔터)
crown.addMany(['redredLight','redredLight'], true)   // 넣고 바로 전송
crown.clear()                           // 입력창 비우기
crown.listLocked()                      // 미구독이라 못 쓰는 것들
crown.setMax(6)                         // 한 메시지 최대 개수
```

크롬이 콘솔 붙여넣기를 막으면 `allow pasting` 을 입력하고 엔터를 먼저 친다.

## 파일

| 파일 | 월드 | 역할 |
|---|---|---|
| `inject.js` | MAIN (페이지) | 입력창에 이모티콘 삽입, 엔터로 전송 |
| `content.js` | 격리 | 확장 API 담당, 팝업↔페이지 이벤트 중계 |
| `popup.html/js` | 팝업 | 수동 테스트 UI |
| `legacy-websocket-inject.js` | — | 구 방식 보존용. **사용하지 않는다** |

`inject.js` 와 `content.js` 는 서로 변수를 볼 수 없어 `window` CustomEvent
(`crown:ready`, `crown:cmd`, `crown:changed`)로만 통신한다.

## 구독 처리

`emoji-packs` 응답의 `emojiPackLocked` / `emojiTier2Locked` 를 읽어
못 쓰는 이모티콘을 자동으로 걸러낸다. 별도 구독 확인 API 가 필요 없다.

- 미구독 채널 → 팩 전체 잠금
- 티어1만 구독 → 티어2 이모티콘만 잠금

`crown.send()` 는 잠긴 이모티콘이면 예외를 던진다.

## 도배 방지

기본 쿨다운 3초. 치지직 자체 채팅 속도 제한에 걸리면 계정이 일시 차단될 수
있으므로 낮추지 않는 편이 안전하다.

## 알려진 제약

- **약관 확인이 아직 안 끝났다.** 입력창 경유로 바꿔 위험이 크게 줄었지만,
  물리 버튼이 전송을 유발하는 구조는 그대로다. `../문의초안.md` 참고.
- **한 메시지 최대 개수 미확인.** 기본 8개로 두었다. 개수보다 글자 수가 먼저
  걸릴 수 있다 (`{:redredCrownlight:}` 는 20자).
- **DOM 구조 변경에 취약.** contenteditable 을 찾는 방식이라 치지직이 입력창
  구조를 바꾸면 깨진다. WebSocket 방식보다는 덜 취약하지만 무관하지는 않다.
- **전송이 성공했는지 확인하지 않는다.** 엔터를 쏘고 끝이다. 치지직이 도배
  제한 등으로 거부해도 확장은 모른다.
